# CP-0005 处理与验收脚本留档

本目录保存 RUN-0003 这一个研究批次实际使用的整合、导出和验收代码及冻结基线，用于解释和复查 CP-0005 的数据变更。它属于检查点验证材料，不引入新的文献范围或研究阶段。研究规范数据仍位于 temp 的既定逻辑数据集和分片中。

- integrate_cp5.py 是一次性批次整合脚本。它只使用已经提交的 16 次来源访问回执和两份复核报告；已完成后不得重放。
- export_run.py、render_html.py 从完整逻辑 JSONL 生成七个交付产物。
- audit_cp5.py 在既有审计上增加 CP-0004 的 9 条不足结论及 22 条反证保护；不扩展 S19 的历史补证例外。
- cp4-assessments.jsonl 是 CP-0004 已有 68 条 Assessment 的原样冻结副本；SHA 与来源提交见 cp4-assessment-baseline.json。
- check_determinism.py 和 html-smoke.mjs 分别检查七产物字节重生成和十项交互行为。
- storage.py、audit_run.py、audit_cp4.py 留存继承依赖；原始脚本字节不作追溯改写。

## 运行位置与重放边界

这些文件保留本次执行环境的路径和历史依赖定位，属于实际执行代码的留档，不声称在任意新目录中不经配置即可运行。RUN.md 给出本次使用的完整命令；preparation-manifest.json 记录来源和依赖哈希。新的执行环境应先恢复仓库和合法取得的原始资料、核对冻结基线及 S19 历史证据，再明确传入仓库/输出路径并配置相应依赖。不得为了消除路径错误放宽原始审计或替换其证据。

本目录不包含 PDF 原文、截图正文、认证数据或访问令牌。新检查点需要先验证当前规范数据，再建立新的检查点文件；不能把这里的 CP-0005 审计结果当作未来修改的验收。
